# V1.2 Gemini Provider + True Embedding RAG Adapter

## 1. 目标

V1.2 不改变 Airflow、Docker、Priority Queue、Soft Preemption、Recovery、HITL、Precondition 或 Action Verification 的业务语义。

本版解决两个集成问题：

1. 将 Agent 的模型层从“仅 OpenAI-compatible Provider”扩展为可直接使用 Gemini 原生 SDK。
2. 将 V0.5 以来的 feature-hashing 向量侧升级为可选的真实 Gemini Embedding，同时保留 BM25 和 dependency-light hash fallback。

因此 V1.2 的结构是：

```text
Agent Model
├── Heuristic Provider        # 无 Key / CI
├── OpenAI-compatible Provider
└── Gemini Provider           # google-genai

RAG
├── BM25
└── Vector side
    ├── Feature Hashing       # 默认 dependency-light baseline
    └── Gemini Embedding      # 可选真实 semantic embedding
```

## 2. 密钥安全

API Key 只能通过环境变量提供：

```bash
export GEMINI_API_KEY='...'
```

也兼容：

```bash
export GOOGLE_API_KEY='...'
```

仓库、测试、Golden Dataset、Trace 和示例配置中都不能写真实 Key。

如果 Key 曾经粘贴到聊天、Issue、日志或其他外部系统，应先 revoke/rotate，再使用新 Key。

```text

```

### Provider 选择


## 5. Query / Document 非对称格式

Gemini Embedding 2 的 text retrieval 使用不同的 query/document 指令文本。

Document 输入：

```text
title: <title> | text: <section + chunk content>
```

Query 输入：

```text
task: question answering | query: <user query>
```

Embedding 输出在写入 Dense Sidecar 前统一做 L2 normalize，查询向量同样归一化，向量相似度使用 cosine。

## 6. Hybrid Retrieval

V1.2 没有把 BM25 删除。

```text
Query
  ├── BM25 lexical score
  └── vector cosine
       ├── Gemini dense embedding
       └── hashing fallback
          ↓
      weighted fusion
          ↓
      heading bonus
          ↓
        Top-K
```

Gemini 模式默认：

```text
lexical_weight = 0.50
vector_weight  = 0.50
```

Hash baseline 保持 V1.1：

```text
lexical_weight = 0.65
vector_weight  = 0.35
```

可通过：

```bash
PLATFORM_RAG_LEXICAL_WEIGHT
PLATFORM_RAG_VECTOR_WEIGHT
```

覆盖。代码会归一化两个权重。

## 7. Dense Embedding Sidecar Cache

不会每次 Query 都重新调用 embedding API 计算全部文档。

文档向量写入：

```text
$AIRFLOW_STATE_DIR/agent_knowledge/embeddings.json
```

Freshness Key 包含：

```text
knowledge source fingerprint
embedding provider
embedding model
embedding dimension
exact chunk ids
```

只有以下变化才重建：

- Knowledge corpus 改变；
- Chunk ID 改变；
- Embedding Provider 改变；
- Embedding Model 改变；
- Embedding Dimension 改变；
- 显式 `knowledge build --force`。

并发重建使用 `fcntl` 文件锁和临时文件原子替换。

因此正常查询的外部 embedding 成本是：

```text
1 query embedding
+
本地 cached document vectors
```

## 9. 本地验收顺序

### 9.1 dependency-light

```bash
dataops-agent doctor --json
dataops-agent e2e --json
dataops-agent eval-aligned --json
```

### 9.2 Gemini runtime

```bash
dataops-agent doctor --strict --json

dataops-agent ask "软抢占为什么不直接 kill 当前 Stage？" --json
dataops-agent ask "当前 GPU Reservation 和显存情况怎么样？" --json
```

第二个问题必须走 MCP live-state Tool，不能只从 RAG 回答。

### 9.3 Build true embedding index

```bash
dataops-agent knowledge build --force --json
dataops-agent knowledge status --json
dataops-agent knowledge search "Segment 为什么一直拿不到 GPU？" --json
```

`knowledge status` 应看到：

```text
retrieval_mode = gemini_hybrid
embedding.enabled = true
embedding.model = gemini-embedding-2
```

### 9.4 A/B evaluation

Hash baseline：

```bash
PLATFORM_RAG_EMBED_PROVIDER=hash dataops-agent eval-aligned --json
```

Gemini：

```bash
PLATFORM_RAG_EMBED_PROVIDER=gemini dataops-agent eval-aligned --json
```

必须使用同一 V1.1 30 条 chunk-level Golden Set 比较：

```text
Context Recall
Context Precision
MRR
nDCG@K
```

不能为了让 Gemini 得分更高修改 Golden Set。

## 10. Evaluation Provider

V1.1 的 Ragas adapter 现在支持：

```bash
PLATFORM_EVAL_PROVIDER=gemini
```

默认 Gemini Judge：

```text
gemini-3.7-flash
```

默认 Embedding：

```text
gemini-embedding-2
```

该 adapter 走 Google 官方 OpenAI-compatible endpoint，使 Ragas 的 OpenAI adapter 可以继续复用。

DeepEval 仍作为可选 framework adapter；V1.2 没有声称在当前沙箱完成 Gemini DeepEval semantic judge 运行。

## 11. 当前环境明确没有验证的内容

开发沙箱无法访问 PyPI，也没有使用用户暴露过的 API Key，因此本版没有声称完成：

- 真实 `google-genai` 安装；
- 真实 Gemini API generation；
- 真实 Gemini embedding API；
- Gemini mode 的 30-case RAG A/B 分数；
- Gemini Ragas semantic judge 分数。

这些必须由用户本地使用 rotate 后的新 Key 验收。

本版已经完成的是：Provider/Embedding adapter、缓存、配置、fallback、接口契约和 dependency-light automated regression。
