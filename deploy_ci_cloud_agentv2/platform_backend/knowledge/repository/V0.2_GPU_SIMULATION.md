# V0.2 GPU Runtime 与 Mock Stage

## 1. 目标

V0.2 解决本地开发环境没有物理 GPU、也没有真实自动驾驶算法镜像时的平台验证问题。

本版本不模拟平台核心调度逻辑，只模拟外部硬件状态和算法行为：

- GPU Reservation：真实代码
- shared/exclusive：真实代码
- 显存判断：真实代码
- stale reservation 清理：真实代码
- GPU 等待：真实代码
- Stage shell 入口：原脚本
- `validate_json.py`：原校验逻辑
- GPU 硬件：Simulator
- 自动驾驶算法：Mock Stage

核心原则：

> 只替换无法获得的外部资源，不复制一套测试专用调度算法。

## 2. GPU Runtime

新增：

```text
platform_core/gateways/gpu_runtime.py
```

统一接口：

```text
GPURuntime
├── NvidiaSMIRuntime
└── SimulatedGPURuntime
```

### NvidiaSMIRuntime

默认生产实现，通过 `nvidia-smi` 查询：

- GPU ID
- total memory
- used memory
- free memory

并通过 OS PID 状态判断 Reservation 是否仍然有效。

默认不需要增加任何环境变量：

```bash
PLATFORM_GPU_RUNTIME=nvidia
```

### SimulatedGPURuntime

本地实现，使用 JSON 文件保存可跨进程共享的 GPU 硬件状态。

示例配置：

```yaml
# config/gpu_simulator.yaml
gpus:
  - id: 0
    total_memory_mb: 48000
    external_used_mb: 0
  - id: 1
    total_memory_mb: 48000
    external_used_mb: 12000
  - id: 2
    total_memory_mb: 24000
    external_used_mb: 20000
```

其中 `external_used_mb` 表示平台 Reservation 之外的显存占用。

平台自己的 Reservation 仍然存放在原来的：

```text
state/gpu_locks/gpu_<id>.lock
```

因此 Simulator 不会替代 Reservation。

## 3. GPUAllocator

新增：

```text
platform_core/services/gpu_allocator.py
```

原 DAG 中的 GPU 分配规则已切到该共享实现。

GPUAllocator 负责：

- 按 GPU Pool 顺序扫描
- 清理死亡 PID Reservation
- exclusive Stage 要求 Reservation 为空
- shared Stage 避让 exclusive Reservation
- exclusive Stage 检查实际 GPU used memory 阈值
- `effective_free = runtime.free - platform_reserved`
- required memory 校验
- Reservation 写入
- Reservation 释放
- 等待重试

DAG 仍保留原来的函数入口：

```text
acquire_gpu_from_pool()
release_gpu_reservation()
query_gpu_memory_mb()
```

但内部已经委托给：

```text
GPURuntime + GPUAllocator
```

这样生产和仿真使用相同调度算法。

## 4. 本地初始化 Simulator

初始化：

```bash
python scripts/gpu_simulator.py \
  --state /tmp/gpu_simulator.json \
  init \
  --config config/gpu_simulator.yaml
```

查看状态：

```bash
python scripts/gpu_simulator.py \
  --state /tmp/gpu_simulator.json \
  show
```

修改 GPU0 外部显存：

```bash
python scripts/gpu_simulator.py \
  --state /tmp/gpu_simulator.json \
  set-memory \
  --gpu 0 \
  --used-mb 30000
```

模拟 PID 已死亡：

```bash
python scripts/gpu_simulator.py \
  --state /tmp/gpu_simulator.json \
  set-pid \
  --pid 12345 \
  --dead
```

Airflow/平台使用 Simulator 时设置：

```bash
export PLATFORM_GPU_RUNTIME=simulated
export PLATFORM_GPU_SIM_CONFIG=/absolute/path/config/gpu_simulator.yaml
export PLATFORM_GPU_SIM_STATE=/tmp/gpu_simulator.json
```

如果 state 文件已初始化，后续只需要设置 runtime 和 state 即可。

## 5. Mock Stage

新增：

```text
scripts/mock_stage.py
scripts/run_mock_stage.sh
```

支持五种结果：

```text
success
fail
timeout
validate_fail
oom
```

### success

写出：

```text
results_<stage>.json
```

状态为 `success`，可以通过现有 `validate_json.py`。

### fail

写失败结果并返回非 0 exit code。

### validate_fail

算法进程返回 0，但结果 JSON 的 `status=failed`。

用于验证：

```text
算法执行成功 != Validate成功
```

### oom

返回 137，并输出模拟 CUDA OOM 日志。

### timeout

进程持续运行，等待调用方 timeout/kill。

## 6. 原 Stage shell 的 Mock 开关

以下原脚本均已支持 Mock：

```text
run_precheck.sh
run_parser.sh
run_segment.sh
run_map.sh
run_od.sh
run_occ.sh
run_coloration.sh
```

默认：

```bash
PLATFORM_STAGE_RUNTIME=real
```

行为完全保持原样。

本地开发：

```bash
export PLATFORM_STAGE_RUNTIME=mock
```

例如：

```bash
export DATASET_PATH=/tmp/record
export DATASET_NAME=clip_001
export DATA_DIR=/tmp/record/clip_001
export PLATFORM_STAGE_RUNTIME=mock

bash scripts/run_segment.sh
```

不需要：

- Docker image
- NVIDIA GPU
- checkpoint
- OD model

仍然会生成：

```text
/tmp/record/clip_001/results_segment.json
```

并可以使用原 Validator：

```bash
python scripts/validate_json.py \
  --root-dir /tmp/record \
  --dataset clip_001 \
  --task-suffix segment \
  --min-date 2020-01-01
```

## 7. 按 Stage 控制行为

全局默认：

```bash
export MOCK_STAGE_RESULT=success
export MOCK_STAGE_DURATION_SEC=0
```

Stage 单独覆盖：

```bash
export MOCK_STAGE_RESULT_SEGMENT=oom
export MOCK_STAGE_DURATION_SEC_OD=10
```

优先级：

```text
MOCK_STAGE_RESULT_<STAGE>
    > MOCK_STAGE_RESULT
    > success
```

Duration 同理。

## 9. 本地功能边界

V0.2 可以在没有 GPU 的机器完成 GPU 调度和 Stage 生命周期开发。

当前沙箱没有安装 Airflow，因此直接 import Airflow DAG 的旧测试仍无法执行；这不影响 V0.2 的 Core GPU 算法测试，因为 DAG GPU 分配已委托给经过测试的 `GPUAllocator`。

真实 Airflow 环境部署时，默认仍使用：

```text
PLATFORM_GPU_RUNTIME=nvidia
PLATFORM_STAGE_RUNTIME=real
```

因此 V0.2 不改变默认生产路径。
