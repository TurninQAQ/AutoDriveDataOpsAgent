# V0.9 Evaluation + Observability

## 1. 目标

V0.9 不扩大 Agent 的业务权限，也不修改 Airflow / Queue / GPU / Docker 的状态机。

本版本只解决两个工程问题：

1. Agent 每次请求、审批和写操作都可以追踪、审计和关联。
2. Agent 的 Intent、Tool Selection、Diagnosis、Safety、Task Planning 和 Action Verification 可以通过固定数据集做确定性回归。

最终链路：

```text
request
  -> plan
  -> retrieval
  -> MCP tool
  -> approval (write only)
  -> mutation (approved write only)
  -> verification
  -> response
```

## 2. Trace / Audit

新增 `platform_observability/`。

### Trace

每个 Agent 请求生成独立 `trace_id`。

写操作第一次请求生成 origin trace；用户后续执行 `approve <approval_id>` 时生成新的 execution trace，并通过 `parent_trace_id` 指向 origin trace。

因此可以关联：

```text
Agent Request Trace
    -> PendingApproval.trace_id
        -> Approval Execution Trace.parent_trace_id
            -> Mutation
            -> Verification
```

Trace 以 JSONL 持久化，每个 trace 一个文件：

```text
$PLATFORM_AGENT_TRACE_DIR/<trace_id>.jsonl
```

默认：

```text
$AIRFLOW_STATE_DIR/agent_traces
```

### Audit

每次请求结束后写一条聚合 Audit Record：

- trace_id / parent_trace_id
- request kind
- thread_id
- user request
- intent
- tool args/result
- approval
- mutation
- verification
- error
- latency
- response summary

默认文件：

```text
$AIRFLOW_STATE_DIR/agent_audit/audit.jsonl
```

### Secret Redaction

所有 Trace/Audit 数据在写盘前统一经过 redaction。

至少处理：

- password / passwd
- token / access_token / refresh_token
- api_key
- secret
- authorization
- cookie
- private_key
- Bearer token
- OpenAI `sk-*` key
- `OPENAI_API_KEY=...`
- `AIRFLOW_API_TOKEN=...`

Trace 中长字符串同时受 `PLATFORM_AGENT_TRACE_MAX_VALUE_CHARS` 限制，避免日志或 Tool Result 无限膨胀。

## 3. Observed MCP Tool Client

新增 `ObservedToolClient`，透明包裹现有 MCP Tool Client。

它不改变 Tool Contract，只记录：

```text
tool_name
arguments
result/error
status
```

Write Tool 自动标记为 `mutation` stage。

因此不需要在每一个 Platform Tool 内部重复增加 tracing 代码。

## 4. Approval / Verification Trace

`PendingApproval` 新增：

```text
trace_id
execution_trace_id
```

- `trace_id`：创建审批的 Agent 请求。
- `execution_trace_id`：真正 approve 后执行 mutation / verification 的请求。

审批执行 Trace 包含：

```text
approval_claimed
mutation
verification
approval_executed / approval_verification_failed
```

V0.8 的业务语义保持不变：

```text
Write Tool ok != Business Success
```

只有 Verification 通过才是 `executed`。

## 5. CLI

新增：

```bash
dataops-agent traces --limit 50

dataops-agent trace <trace_id>

dataops-agent eval
```

`ask` 返回中同时暴露 `trace_id`，方便从用户请求直接定位 Trace。

## 6. Agent Evaluation

新增：

```text
platform_eval/
eval/agent_cases.json
```

统一 Eval 包含六类指标：

```text
intent_accuracy
tool_selection_accuracy
diagnosis_accuracy
unsafe_action_rate
task_planning_accuracy
verification_accuracy
```

### Intent / Tool Selection

直接使用本地 deterministic `HeuristicReadOnlyModel` 检查：

- health
- task status
- stuck diagnosis
- GPU diagnosis
- Stage failure
- platform knowledge

### Diagnosis

使用固定 MCP Evidence Fixture，运行真实 Sequential Agent synthesis：

- GPU 显存不足
- draining / soft preemption
- Stage CUDA OOM

### Safety

检查：

- delete
- stop
- priority
- unsupported restart

Write Intent 可以生成 frozen `write_action`，但 `tool_calls` 里出现 Write Tool 即判定为 unsafe。

指标：

```text
unsafe_action_rate
```

### Task Planning

直接复用 V0.6：

```text
eval/task_planning_cases.json
```

### Action Verification

直接复用 V0.8 deterministic Verification Contract，用固定 Snapshot 检查：

- priority success
- priority not persisted
- stop container residue
- delete success

## 7. 当前固定 Eval 结果

```text
intent_accuracy         = 1.000
tool_selection_accuracy = 1.000
diagnosis_accuracy      = 1.000
unsafe_action_rate      = 0.000
task_planning_accuracy  = 1.000
verification_accuracy   = 1.000
overall_score           = 1.000
```

这些结果来自 deterministic fixture，不代表真实线上 LLM 的泛化准确率。

它们用于保证代码、Prompt Policy、Tool Contract 和规则修改后不发生已知行为回退。

## 8. 环境变量

```text
PLATFORM_AGENT_TRACE_ENABLED=1
PLATFORM_AGENT_TRACE_DIR=
PLATFORM_AGENT_AUDIT_FILE=
PLATFORM_AGENT_TRACE_MAX_VALUE_CHARS=16000
```

空路径由 Runtime 自动解析到 `$AIRFLOW_STATE_DIR`。

## 9. 明确不做

V0.9 不做：

1. 不增加新的 Write Action。
2. 不修改 Priority / Soft Preemption / Recovery。
3. 不增加自动修复闭环。
4. 不做 Multi-Agent。
5. 不做 Web UI / Dashboard。
6. 不把 Trace 写入 Airflow Metadata DB。
7. 不要求外部 tracing SaaS。
8. 不使用真实 GPU 作为 Eval 前提。
9. 不要求真实 LLM API Key 才能运行 Eval。

## 10. 后续建议

V0.9 已完成最初 Agent 化路线的核心闭环：

```text
Platform Core
GPU Simulator
MCP
Read-only Agent
RAG
Task Planning
HITL Write
Action Verification
Evaluation + Observability
```

下一阶段不建议继续机械增加版本功能。

优先做：

1. 安装真实 `mcp/langgraph` 依赖后的协议 smoke test。
2. 在本地完整 Airflow Runtime 中跑 end-to-end scenario。
3. 根据真实运行发现的问题再决定是否做 V1.0 hardening。
4. 若后续有真实历史故障数据，再扩充 Diagnosis Eval，而不是堆功能。
