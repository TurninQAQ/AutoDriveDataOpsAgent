# C. Persistent Idempotency Correctness Closure

`proposal_id` is now part of the recomputed PendingAction fingerprint together with action/args/artifact/global precondition/action-specific precondition.

Semantics:

- retry/restart of the **same** approved PendingAction -> same fingerprint -> persistent dedupe
- a later **new Proposal / new human approval** with identical semantic content -> new runtime `proposal_id` -> new fingerprint -> may execute again
- tampering with `proposal_id`, args, artifact, or preconditions after freeze -> recomputed fingerprint mismatch -> blocked before mutation

Regression coverage includes the reproduced sequence: verified priority change -> external reset to the original state -> new independent proposal with the same requested priority -> second mutation is allowed and independently verified.

# G. Benchmark

The old hard-coded outcome table has been removed.

The benchmark runner now uses:

- 40 cases: READ / WRITE / MIXED / FAULT
- deterministic `BenchmarkScriptedProvider`
- real production Guarded `AgentRuntime` / LangGraph / MCP path
- isolated deterministic simulated benchmark platform
- actual tool traces, mutation records, platform state and FinalGuard result to compute metrics

Naive ReAct and Generic HITL now have distinct control flows. Naive dispatches the candidate directly; Generic HITL records a candidate, human approval, and then executes an intentionally *unbound* candidate without the frozen-core precondition/revalidation/verification protections. Benchmark cases load `initial_platform_fixture`, distinguish `requested_mutation` from `expected_safe_mutation`, and evaluate `expected_final_state`. False Success is derived from a `write_verified` claim whose observable business effect does not match the requested ground truth. Transport fault coverage includes both drop-before-effect and effect-committed-then-response-drop semantics. The guarded runner also fail-closes when an explicit resume target's latest run changes after review.

The benchmark runner was executed from the release source and generated `benchmark_results.json`, `benchmark_results.csv`, and `benchmark_summary.md`. GuardedReAct results: 40/40 cases, task success 1.0, false success 0.0, unsafe write 0.0, wrong target 0.0, tool selection 1.0. Naive and Generic HITL retain their intentionally weaker baseline results. This remains an offline deterministic benchmark, not a live external-Qwen benchmark.
