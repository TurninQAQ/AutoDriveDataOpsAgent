# V3.1 Correctness Closure — Resume Reliability Pass

This pass keeps the V3.1 architecture unchanged and closes the remaining Resume-specific TOCTOU and verification-baseline invariants found after the previous correctness review.

## Newly closed WRITE invariants

### 1. Idempotency is Runtime-derived, not trusted from PendingAction state

`PendingAction.idempotency_key` has been removed. `WriteService` now executes:

```text
actual_fingerprint = recompute(action + args + artifact + precondition)
approved_fingerprint == stored_fingerprint == actual_fingerprint
idempotency_key = "write_" + actual_fingerprint
```

All result-cache and mutation-attempt bookkeeping uses that Runtime-derived key. A hostile or stale workflow field therefore cannot mint a second side-effect attempt for the same approval. Regression coverage includes a verification-failed first attempt followed by an attacker-injected alternate key; mutation count remains one.

### 2. Resume / Stop use action-specific verification contracts

`resume_task` no longer verifies from any historical `success` / `running` DagRun. Verification receives the frozen before snapshot and the post-write snapshot, then requires a **new run id** in a progressing state for **every approved dataset**. Runs for another dataset or old successful runs do not count.

`stop_task` verifies target execution quiescence:

- no running target containers;
- no target GPU reservation;
- no active target Airflow run;
- for whole-task stop, queue location must be `not_found`;
- critical observation errors fail closed.

Partial dataset stop does not require unrelated datasets or the whole task to disappear from the queue.

### 3. `resume_task(datasets=None)` is frozen before HITL

The legacy backend interprets `datasets=None` dynamically by querying failed Airflow runs at mutation time. V3.1 now resolves that dynamic scope in `PendingActionFactory` before review:

```text
Proposal(datasets=None)
-> runtime READ current failed runs
-> datasets=[A, B, ...]
-> before snapshot
-> fingerprint
-> HITL review
```

If there are no failed datasets, no reviewable PendingAction is created. The human therefore approves an explicit target list and Runtime executes that exact list.

### 4. Mixed/parallel Proposal rejection preserves Native Function Calling history

If a model emits a mixed round such as READ + Proposal, the batch is rejected by policy, but every assistant `tool_call_id` now receives its own `role=tool` error message. This preserves a complete native function-calling transcript for the next model invocation.

### 5. Resume uses one fail-closed approval snapshot

For `resume_task(datasets=None)`, the Runtime now performs exactly one action snapshot before review. That single snapshot is used both to resolve the latest failed dataset set and as the `before` verification baseline:

```text
Snapshot S0
-> derive latest FAILED datasets
-> freeze datasets=[A, B, ...]
-> before=S0
-> bind before hash in action_precondition
-> fingerprint
-> HITL
```

There is no second Airflow snapshot between target resolution and baseline capture. Resume never falls back to `get_task_detail` when action-snapshot evidence is unavailable; observation failure blocks creation of a reviewable PendingAction. Dataset resolution also considers only each dataset's **latest** observed DagRun, so an old failed run beneath a newer running/success run does not make the dataset reviewable as a failed target.

### 6. Resume stale approvals get action-specific revalidation

The global queue/config precondition remains lightweight. `WriteService` now adds a narrow action-specific revalidation immediately before the mutation-attempt boundary:

```text
fingerprint validation
-> global precondition recheck
-> resume-specific revalidation
-> runtime-derived idempotency / mutation-attempt gate
-> WRITE
```

For a resume target list that was dynamically derived from failed runs, every approved dataset must still have `FAILED` as its latest observed DagRun state. If another actor has already moved `A` to `RUNNING`, the same queue/config precondition can still match, but V3 returns `PRECONDITION_FAILED` and performs zero mutations. Historical failed runs do not satisfy this check when a newer run exists.

The Resume `before` snapshot is also hash-bound through the action-specific precondition, which itself participates in the approval fingerprint. This prevents mutation of the run-id verification baseline after review. Explicit dataset re-runs retain backend semantics (they are not forced to be failed), while still requiring a complete fail-closed before snapshot and a bound baseline.

## MCP mainline integration closure

The default local Agent runtime no longer bypasses MCP protocol semantics:

```text
Local
AgentRuntime.local
-> OfficialMCPClient(MCPServer)
-> official in-process MCP transport

Remote
AgentRuntime.remote
-> OfficialMCPClient(URL)
-> Streamable HTTP
```

`AgentRuntime.in_process` remains only as a backward-compatible alias of the official local path. The custom registry-only `InProcessMCPClient` is used by pure unit tests, not by the default CLI/runtime mainline. The declared dependency is now `mcp>=2,<3`.

## Previously closed invariants retained

- fingerprint recomputation blocks args/artifact/precondition tamper;
- nested submit YAML tamper is blocked before mutation;
- delete verification is fail-closed across config/DAG/Airflow/Docker/GPU/queue evidence;
- submit verifies exact reviewed config read-back;
- critical observation errors are not absence evidence;
- FinalCandidate is structured and final WRITE status/wording is Runtime-owned;
- shared ToolDefinition registry drives Agent/Runtime MCP profile registration;
- Pydantic constraints feed MCP/native tool schemas;
- Qwen Native Function Calling and parallel tool calls remain enabled;
- ContextBuilder preserves complete tool-call groups;
- lifecycle audit and V3 CLI remain intact;
- V2 production implementation remains unchanged.
