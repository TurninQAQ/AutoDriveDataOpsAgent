# V3.5 MCP Mounted-Server Lifespan Closure

This pass does not change the Guarded ReAct or WRITE architecture. It closes the remaining Standard MCP Streamable HTTP host-integration issue.

## Invariant

`MCPServer.streamable_http_app()` creates the Streamable HTTP session manager. When that child ASGI app is mounted under a parent Starlette/FastAPI application, the child lifespan is not executed. Therefore the top-level host app must own the lifespan and enter every mounted server's `session_manager.run()` context.

V3.5 now builds both child apps first and then starts both Agent and Runtime session managers from one parent Starlette lifespan using `AsyncExitStack`.

```text
Host Starlette lifespan
├── Agent MCP session_manager.run()
└── Runtime MCP session_manager.run()

routes
├── /mcp/agent   -> Agent MCP Streamable HTTP app
└── /mcp/runtime -> Runtime MCP Streamable HTTP app
```

This applies to the real v2 `MCPServer` path and is no longer limited to the legacy FastMCP compatibility branch.

## Validation gate

The release contains:

- a dependency-independent regression test proving the parent lifespan enters both mounted session managers;
- official SDK in-process profile/tool-call integration tests;
- an actual uvicorn + Streamable HTTP smoke test;
- LangGraph ReAct/HITL interrupt-resume E2E tests.

The official SDK and LangGraph tests must be executed in an environment with `mcp>=2,<3` and `langgraph==1.2.11` installed before declaring the MCP/Graph integration independently verified.
