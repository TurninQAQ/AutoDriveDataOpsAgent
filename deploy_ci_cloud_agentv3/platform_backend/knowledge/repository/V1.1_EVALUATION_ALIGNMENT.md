# V1.1 Evaluation Alignment

## 1. 目标

V1.1 不增加新的业务 Tool，不修改 Airflow、Soft Preemption、Recovery 或 GPU Reservation 生产语义，只重构评测体系，使项目与主流 RAG / Agent evaluation 方法对齐。

V1.0 之前的 deterministic pytest / fixture eval 保留，但重新定位为 **Regression Layer**，不再把它等同于完整的 Agent quality evaluation。

## 2. 四层评测体系

```text
Layer 1  Deterministic Regression
         pytest + simulator + platform state assertions

Layer 2  RAG Component Evaluation
         chunk-level golden + retrieval metrics
         + optional Ragas semantic judge

Layer 3  Agent Component / Task Evaluation
         tool/argument correctness
         + environment-first hard task success
         + optional DeepEval semantic/trajectory metrics

Layer 4  Security / Red Team
         curated deterministic attacks
         + optional Promptfoo dynamic red team
```

原则：能由真实系统状态确定的内容不交给 LLM Judge；只有语义质量、faithfulness、answer relevancy、trajectory task completion 等无法用确定性断言覆盖的部分才使用 Judge。

## 3. RAG Eval

### 3.1 Golden Set

`eval/v1_1/rag_retrieval.jsonl` 共 30 条，覆盖：

- GPU shared / exclusive / timeout / simulator / wait
- priority / soft preemption / draining / recovery
- Validate / OOM / Stage failure
- Docker identity / token matching / cleanup
- Airflow health / PostgreSQL
- control-plane architecture / state sources
- grounding / prompt injection

Ground truth 精确到：

```text
source_path#markdown_section
```

长 section 可进一步使用：

```text
source_path#section::chunkN
```

每条 case 同时保存 `reference_answer` 和 `required_facts`，为 semantic generation eval 提供 reference。

### 3.2 Retrieval 指标

Dependency-light suite 计算：

- Context Recall
- Ragas-style Context Precision（按相关 chunk 排名计算 average precision）
- Precision@K
- Hit@K
- MRR
- nDCG@K

当前 baseline 不是满分，这是有意保留的真实差距；后续替换 embedding / vector index / reranker 时用同一 Golden Set 对比。

### 3.3 Generation 指标

`rag_generation_cases.jsonl` 选取 12 条代表性 case，用于可选 Ragas semantic judge：

- ContextPrecision
- ContextRecall
- Faithfulness
- AnswerRelevancy
- AnswerCorrectness

运行需要 `requirements-eval.txt` 和 Judge API Key。

## 4. Agent Tool Eval

`agent_tool_cases.jsonl` 共 21 条。

评测不再要求唯一固定 trajectory，而是声明：

```text
required tools
optional tools
forbidden tools
expected argument subset
required order (only when contract requires it)
```

Dependency-light 指标：

- Tool Precision
- Tool Recall
- Tool F1
- Argument Accuracy
- Forbidden Tool Call Rate
- Ordering Accuracy

可选 DeepEval adapter 使用真实模型 plan，接：

- ToolCorrectnessMetric
- ArgumentCorrectnessMetric

TaskCompletionMetric 不从 fixture trace 伪造；它应绑定有 DeepEval tracing 的真实 Agent execution。

## 5. Task / Environment Eval

`agent_task_cases.jsonl` 共 13 条，使用 realistic platform fixtures：

- GPU memory insufficient
- draining
- CUDA OOM
- delete / stop / priority / restart safety
- priority verification success/failure
- stop container residue
- delete container leak

核心指标是：

```text
Hard Task Success Rate
```

写操作成功必须以最终 Queue / Config / Container / Reservation / Airflow state 为准，而不是 Agent response 文本。

Task Planning 继续复用 `eval/task_planning_cases.json` 的结构化 exact/subset checks。

## 6. Security Eval

### 6.1 Dependency-light curated attacks

`security/curated_attacks.jsonl` 共 12 条。

Scorer 的主标准是 forbidden capability 是否被模型直接执行；不把“没有输出我们偏好的 intent”错误视为安全失败。

### 6.2 Promptfoo

提供：

```text
eval/v1_1/security/promptfooconfig.yaml
eval/v1_1/security/promptfoo_provider.py
eval/v1_1/security/assertions.py
```

覆盖风险：

- excessive-agency
- system-prompt-override
- indirect-prompt-injection
- rag-poisoning
- MCP abuse
- shell-injection
- prompt-extraction

支持 curated eval，也可在安装 Promptfoo 和攻击模型后运行 dynamic red team。

## 7. CLI

### Dependency-light 主门禁

```bash
dataops-agent eval-aligned
```

默认门槛来自：

```text
eval/v1_1/thresholds.json
```

### 检查可选框架

```bash
dataops-agent eval-frameworks
```

### Ragas

```bash
PLATFORM_INSTALL_EVAL_DEPS=1 ./platform install
export OPENAI_API_KEY=...
dataops-agent eval-ragas
```

### DeepEval

```bash
dataops-agent eval-deepeval
```

### Promptfoo

```bash
dataops-agent eval-promptfoo
# 或已配置攻击模型时：
dataops-agent eval-promptfoo --redteam
```

## 8. 安装策略

Ragas/DeepEval 是可选评测依赖，不进入默认 runtime dependency：

```text
requirements-eval.txt
```

只有：

```bash
PLATFORM_INSTALL_EVAL_DEPS=1 ./platform install
```

才安装。

这保证生产调度平台不会因为评测框架引入额外重量或依赖冲突。

## 9. 当前限制

1. 当前开发环境未安装 Ragas/DeepEval，因此 native adapter 只验证 import-safe / fail-clean contract，未声称已经跑过 Judge API。
2. 当前没有外部 LLM Key，因此 semantic judge 分数不作为 V1.1 release gate。
3. Promptfoo dynamic red team 需要 Promptfoo CLI 和攻击模型 provider；本地 curated attacks 可无外部模型运行。
4. 当前 RAG 仍是 BM25 + feature-hashing hybrid，V1.1 只把评测基线做好，不在本版替换 retrieval 技术。
5. 当前 full Airflow import tests 仍受沙箱缺少 Airflow package 限制。

## 10. 后续改进顺序

V1.1 以后如果继续优化，优先以 eval 结果驱动：

1. 用真正 Embedding + Vector Index 替换 feature hashing。
2. 在相同 30 条 chunk-level Golden Set 上比较 Context Recall / Precision / nDCG。
3. 必要时增加 reranker。
4. 使用真实 LLM 跑 Ragas / DeepEval。
5. 从真实使用日志和历史 incident 扩充 holdout dataset，而不是只增加“容易通过”的 Case。
