# V0.4 Read-only Agent

## 1. 版本目标

V0.4 在 V0.3 Platform MCP Server 的 8 个只读领域 Tool 之上增加单 Agent。

本版本只解决：

- 平台健康查询
- 任务列表
- Task 状态查询
- Task 卡住/不运行诊断
- GPU 资源诊断
- Stage 失败与日志诊断
- Thread 级短期会话状态

本版本明确不执行任何平台写操作。

---

## 2. 架构

```text
User / CLI
    |
    v
ReadOnlyPolicy
    |
    v
Plan Node
    |
    +---- no tool ----> Answer Node
    |
    v
MCP Tool Node
    |
    v
Answer Node
    |
    v
Structured AgentResponse
```

正式 Runtime：

```text
LangGraph StateGraph
+ InMemorySaver
+ file-backed ConversationStore
```

Agent 访问实时平台状态必须经过：

```text
Agent
 -> MCP Client
 -> Platform MCP Server
 -> Platform Core
 -> Airflow / Queue / Docker / GPU
```

默认 MCP Client 使用官方 MCP v2 的 in-memory transport：Agent 和 MCP Server 位于同一 Python 进程，但仍经过 MCP Client/Server 协议接口，不直接访问 Platform Core。

---

## 3. 为什么同时保留 Sequential Runtime

`SequentialReadOnlyAgent` 不是生产替代方案，只用于：

- 当前无网络沙箱无法安装 LangGraph 时跑确定性回归
- 单元测试 Agent Node
- Debug plan/tool/answer 的边界

正式安装会安装 `requirements-agent.txt`，默认 `PLATFORM_AGENT_RUNTIME=langgraph`。

两种 Runtime 共用同一个：

- `ReadOnlyAgentNodes`
- Model 接口
- MCP Tool Client 接口
- ReadOnlyPolicy
- ConversationStore
- AgentResponse Schema

因此测试的不是另一套业务逻辑。

## 4. Model Provider

### 4.1 auto

默认：

```bash
PLATFORM_AGENT_PROVIDER=auto
```

行为：

- 有 `OPENAI_API_KEY` 或 `OPENAI_BASE_URL`：使用 `OpenAIReadOnlyModel`
- 否则：使用 `HeuristicReadOnlyModel`

### 4.2 heuristic

用于无 API Key 环境开发和回归。

它可以确定性完成 V0.4 的意图路由和基础 Evidence 分析，但不作为最终智能能力上限。

### 4.3 openai

```bash
PLATFORM_AGENT_PROVIDER=openai
PLATFORM_AGENT_MODEL=<model>
OPENAI_API_KEY=<key>
```

使用 `langchain-openai`：

- Planner 使用 `AgentPlan` Pydantic structured output
- Synthesizer 使用 `AgentResponse` Pydantic structured output

日志、Tool Result、历史对话全部明确作为 untrusted data 进入提示词，不能被当成系统指令。

## 5. Stateful 设计

### 5.1 LangGraph Checkpoint

LangGraph 使用 `InMemorySaver` 保存一次进程生命周期内的 Graph state，并以：

```text
thread_id
```

作为 Graph thread key。

### 5.2 ConversationStore

为了 CLI 进程退出后仍可保留短期历史，增加文件化：

```text
$AIRFLOW_STATE_DIR/agent_sessions/<thread_id>.jsonl
```

只保存：

- user text
- assistant summary
- intent

不保存大量原始日志和 Tool Evidence，避免历史无限增长。

## 6. Read-only Policy

V0.4 有两层只读约束。

### 第一层：请求级拦截

`ReadOnlyPolicy` 在 Model 之前识别明显写请求，例如：

- submit
- stop
- delete
- resume
- restart
- 修改 priority
- “让某任务先跑”

命中后：

```text
intent = unsupported_write
tool_calls = []
```

不会调用模型进行 Tool Planning，也不会调用 MCP Tool。

### 第二层：Tool Allowlist

即使模型产生错误计划，也只能调用 V0.3 的：

```text
get_platform_health
list_tasks
get_task_detail
get_queue_state
get_gpu_pool
inspect_task_containers
get_stage_logs
diagnose_task
```

任何其他 Tool 直接 `PermissionError`。

## 7. Agent Intent

V0.4 固定：

```text

list_tasks
task_status
task_diagnosis
gpu_diagnosis
stage_failure
general_read
unsupported_write
```

## 8. Agent Output

统一输出 `AgentResponse`：

```json
{
  "intent": "gpu_diagnosis",
  "summary": "...",
  "root_cause": "...",
  "evidence": [],
  "recommended_next_actions": [],
  "confidence": "high",
  "blocked": false,
  "errors": [],
  "tool_trace": []
}
```

不输出隐藏 Chain-of-Thought。

只输出：

- 结论
- Evidence
- Root Cause
- 下一步建议
- Tool Trace

## 9. CLI

安装后：

```bash
$RUNTIME_DIR/bin/dataops-agent ask "release_xxx 现在是什么状态？"
```

JSON：

```bash
$RUNTIME_DIR/bin/dataops-agent ask "release_xxx 为什么没跑？" --json
```

指定 Thread：

```bash
$RUNTIME_DIR/bin/dataops-agent ask "release_xxx 怎么了？" --thread-id incident-001
```

本地终端对话：

```bash
$RUNTIME_DIR/bin/dataops-agent chat --thread-id incident-001
```

查看 Agent 能看到的 MCP Tool：

```bash
$RUNTIME_DIR/bin/dataops-agent tools
```

## 10. 依赖

`requirements-agent.txt`：

```text
langgraph==1.2.11
langchain-openai==1.5.2
```

MCP 仍使用：

```text
mcp==2.0.0
```

`platform install` 会依次安装 Airflow、MCP 和 Agent 依赖。

---

## 11. 本版本没有做

- RAG
- Vector Store
- Write Tools
- HITL
- submit task
- priority 修改
- stop/delete/resume
- Action Verification
- Multi-Agent
- Web UI
- HTTP Agent API
- 持久化 LangGraph DB Checkpointer

这些都不应该偷偷混入 V0.4。

---

## 12. 下一版本

V0.5：RAG + Runbook。

重点是把以下静态知识接入 Agent：

- 平台架构
- Task 生命周期
- GPU 调度规则
- Priority / Soft Preemption
- Recovery
- usage/deploy 文档
- 故障 Runbook

必须继续保持边界：

```text
实时状态 -> MCP Tool
静态知识 -> RAG
```
