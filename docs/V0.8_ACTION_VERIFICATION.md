# V0.8 Action Verification

## 目标

V0.7 已有：

```text
Observe -> Impact -> HITL Approval -> Precondition -> Act
```

V0.8 补成：

```text
Observe -> Impact -> HITL Approval -> Precondition -> Act -> Observe Again -> Verify
```

Write MCP Tool 返回 `ok=true` 只表示调用过程没有直接失败，不等于业务目标已经达成。V0.8 只有在后验验证通过后才把 Approval 标记为 `executed`。

如果写操作已经真实执行，但平台状态没有达到预期，则：

```text
status=verification_failed
```

同时保留 `execution_result` 和 `verification_result`。

## 内部 Verification Snapshot

新增内部 MCP Tool：

```text
get_action_verification_snapshot
```

该 Tool 不放入模型可见的 `READ_ONLY_TOOL_NAMES`，只供 HITL 写执行器使用。

它聚合：

- Task config / generated DAG file
- priority / task_exclusive
- global queue status
- task-owned Docker containers
- task-owned GPU Reservations
- Airflow DAG metadata
- DagRuns
- evidence collection errors

与普通 task detail 不同，该 Snapshot 在 Task YAML 已被 `delete_task` 删除后仍可工作，因此还能继续确认容器、Reservation、Queue 和 Airflow metadata 是否清理干净。

## Action Contracts

### submit_task

验证：

1. Task config 存在。
2. generated DAG file 存在。
3. priority 与提交配置一致。
4. task_exclusive=true 时，任务进入 active/queued。
5. 预期 Dataset 对应 DagRun 已可观察。

真实 task name 从 Write Tool result 获取，不从 task prefix 猜测。

### set_task_priority

验证：

1. Task config 仍存在。
2. config priority 等于目标值。
3. 如果任务仍处于 global queue，queue entry priority 同步更新。

### stop_task

验证：

1. Task config 保留。
2. 目标容器已回收。
3. 目标 GPU Reservation 已回收。
4. 停整个 Task 时 Queue 中已移除。
5. Approval baseline 中处于 active 的目标 DagRun 不再 active。

### resume_task

Approval 创建时保存 Verification Baseline。

执行后验证：

1. Task config 仍存在。
2. 显式 Dataset 必须出现新的 DagRun。
3. 未指定 Dataset 时，从 baseline failed DagRun 推导恢复目标。
4. task_exclusive=true 时重新进入 active/queued。
5. baseline 无 failed Dataset 时允许确定性 no-op。

### delete_task

验证：

1. Task config 已删除。
2. generated DAG file 已删除。
3. Queue 中目标 Task 已消失。
4. Task-owned Docker container 为 0。
5. Task-owned GPU Reservation 为 0。
6. Airflow DAG metadata 已不存在。

## Eventual Consistency

Airflow、Queue 和文件状态可能晚于 Write Tool 返回可见，因此 V0.8 只重试 Observe，不重复执行 Write Tool。

配置：

```text
PLATFORM_AGENT_VERIFY_ATTEMPTS=5
PLATFORM_AGENT_VERIFY_INTERVAL_SEC=1.0
```

任意一次满足全部 Contract 即 `verified`；达到最大次数仍不满足则为 `failed` 或 `inconclusive`，均不能报告成功。

## Approval 状态

```text
pending
executing
executed
verification_failed
failed
rejected
expired
```

- `failed`：Write Tool 本身失败，例如 `PRECONDITION_FAILED`。
- `verification_failed`：Write Tool 已执行，但后验验证失败或证据不足。
- `executed`：Write Tool 成功且 Verification 通过。

## 安全边界

V0.8 不扩大模型权限。模型普通 Tool Planning 仍只有 V0.3 的 8 个 read-only tools。Write Tool、Precondition Tool 和 Verification Snapshot 都不会由模型直接调用。

## 本版不做

1. 不自动用 LLM 修复 verification failure。
2. 不重复执行 Write Tool。
3. 不开放 restart_platform。
4. 不做 Multi-Agent。
5. 不做 Web UI。
6. 不移除 legacy task_manager mutation orchestration。
