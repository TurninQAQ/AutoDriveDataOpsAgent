# V0.1 Platform Core 重构

## 目标

V0.1 不改变现有 Airflow/Docker/GPU/任务优先级的业务语义，先把 `scripts/task_manager.py` 中可复用、可测试的能力抽到 `platform_core`，为后续 GPU Simulator、MCP 和 Agent 提供稳定调用边界。

## 已完成

### 1. Platform Core

新增 `platform_core/`：

- `config.py`：任务 YAML、Pipeline、GPU、优先级、Dataset 校验与标准化。
- `task_store.py`：Task 配置持久化、动态 DAG 生成、Dataset 选择。
- `queue_state.py`：Queue 文件读写、优先级排序和优先级刷新。
- `models.py`：TaskService 的结构化返回模型。
- `errors.py`：统一 `TaskConfigError`。

### 2. Services

新增：

- `TaskService`
- `QueueService`
- `DockerService`
- `GPUService`
- `DiagnosisService`

其中 `TaskService` 已接管任务提交前的 YAML 校验、Task 配置安装、动态 DAG 生成和 Priority 更新；CLI 继续负责 Airflow Trigger、Queue Runtime Effects 等运行时编排。

`DiagnosisService` 在 V0.1 建立确定性证据聚合边界，目前聚合 Queue、Docker Container 和 GPU Reservation；Airflow DagRun/TaskInstance 证据将在 MCP 读取能力阶段继续接入。

### 3. Gateways

新增：

- `AirflowGateway`：Airflow CLI / REST 传输边界。
- `DockerGateway`：Docker inspect / stop / container matching 边界。
- `gpu_reservations.py`：GPU Reservation 文件访问边界。
- `GPURuntime`：GPU 硬件状态抽象接口；V0.2 再实现 `NvidiaSMIRuntime` 和 `SimulatedGPURuntime`。

### 4. CLI 兼容

`scripts/task_manager.py` 保留原有函数入口，现有上层调用不需要切换接口。

任务提交和优先级修改已切换为：

```text
CLI -> TaskService -> Platform Core
```

而不是在 CLI 中重复实现配置和文件生成逻辑。

### 5. Runtime 部署兼容

原部署流程只复制 DAG/scripts/config。V0.1 新增 `platform_core` 后，如果不修改部署脚本，Runtime 中的 `task_manager.py` 会 import 失败。

因此 `scripts/deploy_ci_cloud.sh` 已同步复制：

```text
DAG / scripts / platform_core / config
```

并增加部署后的文件存在性检查。

## V0.1 暂不改动

以下运行时状态机仍保持原实现，避免一次性重构影响既有语义：

- 任务级 Queue 状态迁移
- Soft Preemption
- Recovery DagRun
- Airflow DB 内部状态操作
- 定时提交状态机
- Platform Restart Cleanup

后续版本在有足够测试覆盖后再逐步从 `task_manager.py` 迁出。

## 测试

新增 `tests/test_platform_core_v01.py`，覆盖：

- TaskService 任务配置和动态 DAG 生成
- QueueService Snapshot / Task Lookup
- Docker Dataset 完整 Token 匹配
- Stale GPU Reservation 清理
- 原 GPU Config 规则
- AirflowGateway CLI 边界
- Runtime 部署复制 `platform_core`
- 部署后的 `task_manager.py --help` import 验证
- DiagnosisService Evidence 聚合
- GPURuntime 抽象接口

现有不依赖 Airflow 安装的回归测试继续通过。

当前开发环境未安装 Airflow，因此需要直接 import Airflow DAG Runtime 的测试无法在本地执行；V0.1 未修改 DAG Runtime 文件。
