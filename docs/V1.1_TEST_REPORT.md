# V1.1 Evaluation Alignment Test Report

## 1. Release Scope

V1.1 does not add new business capabilities. It rebuilds the evaluation system so that the existing Agent/RAG functionality is tested in four layers:

1. deterministic platform regression;
2. RAG component evaluation aligned to Ragas concepts;
3. Agent tool/task evaluation aligned to DeepEval concepts;
4. curated security regression plus Promptfoo dynamic-red-team configuration.

The dependency-light release gate does not require an external LLM judge, API key, physical GPU, Ragas, DeepEval, or Promptfoo installation.

## 2. Evaluation Datasets

| Dataset | Cases | Purpose |
|---|---:|---|
| `eval/v1_1/rag_retrieval.jsonl` | 30 | chunk-level RAG golden set |
| `eval/v1_1/rag_generation_cases.jsonl` | 12 | optional semantic Ragas judge set |
| `eval/v1_1/agent_tool_cases.jsonl` | 21 | tool selection / argument / forbidden-tool evaluation |
| `eval/v1_1/agent_task_cases.jsonl` | 13 | diagnosis, safety and final-state task evaluation |
| `eval/v1_1/security/curated_attacks.jsonl` | 12 | deterministic security regression |
| `eval/task_planning_cases.json` | 8 | structured task-planning regression reused by V1.1 |

The cases are realistic platform fixtures based on existing project semantics: DagRun/TaskInstance, active/queued/draining, GPU free memory and Reservation, Stage OOM/Validate failure, Container residue, approval/precondition, and Action Verification snapshots.

## 6. Framework Integration Status

`dataops-agent eval-frameworks --json` reports framework availability separately from the dependency-light release gate.

V1.1 provides optional adapters for:

- Ragas semantic generation metrics;
- DeepEval Tool Correctness / Argument Correctness;
- Promptfoo curated and dynamic red-team execution.

Current sandbox constraints:

- Ragas optional package is not installed;
- DeepEval optional package is not installed;
- no external judge API key is configured;
- therefore no native Ragas/DeepEval semantic score is claimed for this release.

The adapters fail cleanly with an installation/configuration error instead of substituting deterministic regression scores for semantic judge scores.

Promptfoo configuration/provider/assertion assets are shipped and statically/smoke tested. Dynamic Promptfoo red-team execution requires an environment with the Promptfoo CLI and attacker/model provider configured.

## 7. Source/Runtime Reproducibility

The source knowledge corpus and the corpus produced by `deploy` were synchronized for V1.1.

A temporary Runtime deployment was evaluated with the same aligned suite. Source and deployed Runtime produce the same release-gate metrics.

This prevents a previous class of error where deploy-time injected documentation changed retrieval rankings relative to source-tree evaluation.

## 8. Bug Found by the New Evaluation

The new tool-routing cases found a real routing defect:

```text
当前 GPU Reservation 和显存情况？
```

The old heuristic could classify this as static `platform_knowledge` because `reservation` matched knowledge terms. V1.1 adds live-state terms (`当前/现在/实时/状态/占用/剩余/current/status/usage/...`) so current-state questions cannot be captured by static RAG intent.

Expected path now:

```text
gpu_diagnosis -> get_gpu_pool
```

This case remains in the Golden Set as a regression test.

## 9. Release Conclusion

V1.1 establishes a mainstream-aligned evaluation structure without pretending that deterministic regression is semantic model evaluation.

The release is accepted because:

- all V1.1 deterministic gates pass;
- the broader dependency-light suite passes;
- source and deployed Runtime baselines are reproducible;
- semantic judge integrations are present but honestly marked optional/unexecuted in the current environment;
- non-perfect RAG retrieval results are preserved as an optimization baseline.
