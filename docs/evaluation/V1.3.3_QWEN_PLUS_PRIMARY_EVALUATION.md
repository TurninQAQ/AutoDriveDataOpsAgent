## 2. Runtime Migration

The default selection path was:

```text
AgentSettings.from_env()
  -> platform_agent.runtime.build_default_agent()
  -> build_model_from_env()
  -> QwenReadOnlyModel
```

Before this version, when `PLATFORM_AGENT_MODEL` was absent and Qwen was
configured, the default was `qwen3.7-flash` in `platform_agent/settings.py` and
in the `platform` runtime environment writer. V1.3.3 changes only those
defaults and the direct Qwen constructor default. Explicit
`PLATFORM_AGENT_MODEL=qwen3.7-flash` remains supported.

## 6. Qwen Plus Agent RAG Evaluation

The existing 12-case dataset was used unchanged:

```text
Agent: qwen-plus
Judge: qwen-plus
Embedding: qwen3.7-text-embedding / 1024
Cases: 12
```

The run reached the Ragas Judge after Agent collection and then blocked in the
first `answer_correctness` Judge request. The traceback showed the wait inside
Ragas 0.4.x Instructor structured-output retry through the DashScope proxy;
the outer metric timeout could not complete cancellation while the inner retry
was waiting on the socket. The process was interrupted after more than ten
minutes to avoid an unbounded quota/network wait.

| Metric | Result |
|---|---|
| Faithfulness | `NOT_VALIDATED` |
| Answer Relevancy | `NOT_VALIDATED` |
| Answer Correctness | `BLOCKED_NOT_VALIDATED` |
| Semantic aggregate | `BLOCKED_NOT_VALIDATED` |

Semantic case accounting:

```text
Cases: 12
Scored success: 0
Scored failure: 0
Blocked: 12
```

No semantic score was converted to zero. The blocked artifact records the
dataset, models, embedding, blocking metric, last successful step, and the
fact that the interrupted process did not flush per-case samples:

`local_acceptance/v1.3.3_qwen_plus_agent_rag.json`

The code now supports an optional pre-Judge checkpoint through
`PLATFORM_EVAL_COLLECTION_ARTIFACT`, and bounds the Ragas internal structured
Judge retry loop with `PLATFORM_EVAL_RAGAS_MAX_RETRIES=1`. Those changes were
verified offline; the API run was not repeated after the block.

The prior qwen-plus RAG artifact remains historical evidence only: its Judge
was qwen-plus, but its Agent responses were generated by qwen3.7-flash. It is
not a qwen-plus Agent RAG baseline.

- Agent and Judge both use qwen-plus, so semantic scores would have self-evaluation bias if the RAG run is later completed.
- Ragas 0.4.x structured Judge behavior through the current proxy requires a later controlled revalidation after the retry-bound fix.
- No physical GPU is available; smoke and deterministic GPU tests use the existing simulator.
- The write smoke did not reach HITL because deterministic TaskSpec validation correctly blocked the unresolved dataset path; no production write was run.
