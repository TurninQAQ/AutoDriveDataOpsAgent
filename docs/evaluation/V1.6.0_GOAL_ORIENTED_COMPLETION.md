# V1.6.0 — Goal-Oriented Diagnosis & Completion

## 1. Why V1.6

V1.5 made read-only evidence collection adaptive:

```text
Observe → Decide → Tool → Observe → Decide Again
```

That solved next-tool selection, but evidence sufficiency alone does not answer
whether the user's requested outcome has been established. V1.6 adds a small
request-level Goal and a deterministic GoalEvaluator.

## 2. Scope and safety boundary

V1.6 covers read-only goal completion and write-action preparation. It does not
add autonomous mutation, resume, retry, risk classification, or a second LLM
judge. Write operations continue to use:

```text
Impact Analysis → HITL → Precondition → Mutation → Verification
```

The Goal layer never chooses a concrete Tool. It reports satisfied and missing
conditions to the Adaptive Agent; Tool selection remains agentic.

## 3. Goal model

`AgentPlan.goal` is optional for backward compatibility. Production structured
providers are instructed to return one of:

```text
ANSWER_KNOWLEDGE
REPORT_LIVE_STATE
DIAGNOSE_ROOT_CAUSE
EXPLAIN_WITH_PLATFORM_RULES
VERIFY_RECOVERY_STATE
PREPARE_TASK_PLAN
PREPARE_WRITE_ACTION
GENERAL_ASSISTANCE
```

When a legacy model omits Goal, the workflow applies a deterministic intent
fallback. The request Goal is fixed for the request; Adaptive steps may revise
read-only intent but cannot revise Goal.

## 4. Deterministic completion

`platform_agent/goal.py` derives criteria from GoalType. Examples:

| Goal | Completion evidence |
| --- | --- |
| `ANSWER_KNOWLEDGE` | `STATIC_KNOWLEDGE` |
| `REPORT_LIVE_STATE` | relevant operational evidence |
| `DIAGNOSE_ROOT_CAUSE` | explicit diagnosis/root-cause signal |
| `EXPLAIN_WITH_PLATFORM_RULES` | operational + static evidence |
| `VERIFY_RECOVERY_STATE` | live task + recovery/checkpoint evidence |
| `PREPARE_WRITE_ACTION` | guarded write plan prepared for approval |

`diagnose_task` alone is not automatically a root cause. The result must contain
an explicit diagnosis signal such as `reason`, `diagnosis` or `root_cause`.

Progress is deliberately small:

```text
NOT_STARTED → IN_PROGRESS → SATISFIED
                         ↘ BLOCKED
```

If the model returns `FINISH` while criteria are incomplete, the workflow returns
`goal_incomplete` with low confidence. It does not force an arbitrary next Tool.

## 5. Architecture

```text
User
  ↓
Goal Interpretation + Initial Plan
  ↓
Read-only?
  ├─ No → existing Task Planning / guarded Write path
  └─ Yes
       ↓
  Goal Check + Adaptive Decide
       ↓
  FINISH? ── yes ──→ Goal Check → Synthesize
       │
       no
       ↓
  ONE Read-only Tool
       ↓
  Tool Observation + Evidence Update
       ↓
  Goal Check
       ↓
  Adaptive Decide ...

  Shared Policy + Loop Budget + Tool Observations + Knowledge normalization
```

Goal progress is passed to the next decision as bounded structured context:
`GOAL`, `GOAL_PROGRESS`, satisfied conditions and missing conditions. No hidden
chain-of-thought is recorded.


Successful trajectories included static knowledge, live task state, root-cause
diagnosis, GPU hybrid, draining hybrid, recovery verification and HITL write
preparation. The Tool Failure case correctly stopped with `goal_incomplete`
instead of claiming success.

The remaining failed scenario was Task Planning: qwen3.7-plus returned a draft
without the required `task_prefix` and dataset path, so the existing deterministic
TaskPlanningService correctly kept the Goal `IN_PROGRESS`. This is a model/task-
draft weakness, not an authorization or mutation failure.

## 8. Known limitations

- GoalType selection remains model-dependent; the shared contract reduces semantic
  ambiguity but is not a keyword router.
- Task Planning still depends on the model preserving explicit draft fields before
  deterministic validation.
- The smoke is not a qwen-plus formal benchmark and must not be compared directly
  with V1.4.x or V1.5 qwen-plus metrics.
- Existing repository-wide historical/environment failures remain outside V1.6:
  old observability evaluation, `task_spec=None` hardening setup, long GPU
  allocator waits, and unavailable deployment `python` executable.
