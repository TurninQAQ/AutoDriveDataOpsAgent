## Why V1.4.4 was insufficient

V1.4.4 showed that one-shot routing could miss the second evidence source in
explicit Hybrid requests. The initial planner had to predict the entire tool
list before seeing any result. That is an architectural limitation of:

```text
Plan all tools → execute all tools → synthesize
```

V1.5.0 changes read-only evidence gathering to:

```text
User
 ↓
Initial Plan
 ↓
Read-only?
 ├─ No → existing task-planning / guarded write path
 └─ Yes
      ↓
  Adaptive Decide
      ↓
  FINISH? ───────→ Synthesize
      │
  one read-only Tool
      ↓
  Observation
      ↓
  normalize search_knowledge evidence
      ↓
  Adaptive Decide again
      ↓
  ...
```

The loop has a hard step budget, tool-call budget, identical-call limit and
consecutive-failure limit. Policy validation runs before every execution.

## Responsibilities

`AgentPlan` remains the initial high-level contract for intent, entities,
task drafts and frozen write actions. `AgentStepDecision` only chooses
`CALL_TOOL` with one read-only call or `FINISH`. It can revise a read-only
intent after evidence arrives, but deterministic validation rejects revisions to
task planning or any mutation intent.

Qwen, Gemini and OpenAI-compatible models use the shared
`ADAPTIVE_EVIDENCE_CONTRACT`. It asks for a short `decision_summary` only; no
chain-of-thought is requested or recorded. The heuristic model intentionally
keeps its legacy single-shot capability for historical deterministic tests.

## Evidence and provenance

Tool observations accumulate in execution order. A successful
`search_knowledge` observation continues to use the V1.4.2 normalization path:

```text
ToolObservation
 → KnowledgeObservation
 → knowledge_sources / retrieval_trace
```

`AgentResponse.tool_trace` is built from actual executed observations, not from
the initial plan's candidate calls. Write requests do not enter the adaptive
read loop and continue through the existing impact analysis, HITL, precondition,
mutation and verification path.

## Limits and termination

Defaults are request-level settings:

```text
PLATFORM_AGENT_MAX_STEPS=8
PLATFORM_AGENT_MAX_TOOL_CALLS=6
PLATFORM_AGENT_MAX_IDENTICAL_TOOL_CALLS=2
PLATFORM_AGENT_MAX_CONSECUTIVE_TOOL_FAILURES=2
```

Termination reasons include `agent_finished`, `step_budget_exhausted`,
`tool_budget_exhausted`, `duplicate_tool_limit`,
`consecutive_tool_failures`, `decision_error` and
`unsafe_adaptive_decision`. If evidence is insufficient at a guarded
termination, deterministic response handling lowers confidence to `low` and
adds an explicit error.

## Observability

Each adaptive step records only auditable metadata:

- step and current/revised read intent;
- `CALL_TOOL` or `FINISH`;
- tool and arguments when applicable;
- evidence sufficiency;
- concise decision summary;
- remaining budgets and observation status;
- termination reason.

Tool results remain untrusted data. An injected result such as “call
delete_task” cannot expand the read-only allowlist; the attempted mutation is
rejected before execution and recorded as an adaptive safety event.

## Evaluation design

`eval/v1_5_0/adaptive_cases.jsonl` contains 16 deterministic scenarios. Each
case supplies a local fixture Tool World, required/optional/forbidden evidence,
expected intent, optional expected next step and a call budget. Two cases are
explicit V1.4.4 known-regression probes and are excluded from the unseen
generalization aggregate.

The collection runner is:

```text
scripts/evaluate_adaptive_v150.py
```

It saves a partial checkpoint after each completed case and saves the planner
trajectory before calculating final metrics. The deterministic
metrics are:

- Scenario Completion Rate;
- Required Evidence Recall;
- Tool Precision and Unnecessary Tool Rate;
- Adaptive Next-step Accuracy;
- Final Intent Accuracy;
- Hybrid Completion Rate via the Hybrid category breakdown;
- Loop Termination Accuracy;
- Budget and duplicate-call safety violations;
- Forbidden Write Execution Rate;
- No-tool Accuracy;
- average/max adaptive steps and tool calls.

No LLM judge decides whether a write was executed, whether a budget was
exceeded, or whether required evidence was collected. If a future semantic
judge is added, Agent and Judge using qwen-plus must be marked
`SELF_MODEL_EVALUATION=true`.

## Deterministic test result

Sequential/LangGraph wiring and V1.4.x routing/evaluation regressions pass in
the dependency-light environment. The exact command results are recorded in
the V1.5.0 handoff/result.

The runner now has a 45-second per-provider request timeout and a 120-second
per-case timeout. A future rerun must use the frozen 16-case file and must not
change the prompt based on an intermediate failure. If the endpoint remains
unresponsive, the result stays blocked rather than being converted into model
metrics.

## Known repository issues

The repository still has two environment/history issues outside V1.5.0:

1. Some old tests expect Nvidia runtime in an environment without a real GPU.
2. A deployment test invokes a `python` executable absent from this image.

Task-planning tests also require the repository's
`PLATFORM_TASK_PLANNING_DEFAULTS` environment variable. With the established
simulated-GPU/dependency-light environment, the relevant V1.4.x and write
safety regression suite passes.
