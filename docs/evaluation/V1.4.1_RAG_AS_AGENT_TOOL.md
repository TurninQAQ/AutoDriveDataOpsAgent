# V1.4.1 RAG as Agent Tool Evaluation

Date: 2026-08-20
Primary Agent Model: `qwen-plus`
Embedding: `qwen3.7-text-embedding`, 1024 dimensions
Status: `PARTIAL`

## Scope

V1.4.1 exposes the existing RAG pipeline as one read-only MCP Tool:

```text
Before:
User → AgentPlan → fixed workflow retrieval → LLM answer

After:
User → Qwen Plus AgentPlan
     → optional search_knowledge MCP Tool
     → ranked retrieval result
     → Qwen Plus answer synthesis
```

This version did not change the Tool Contract of the historical cases, Prompt,
Embedding model, chunking, Vector Store, retrieval algorithm, HITL,
Precondition, Verification, WriteActionCoordinator, provider isolation, or
retry implementation.

## Runtime implementation

The existing pipeline remains:

```text
KnowledgeService.search()
→ KnowledgeIndex.ensure()
→ DenseEmbeddingIndex (when configured)
→ HybridRetriever.search()
→ RetrievedKnowledge
```

The new read-only facade method converts each `RetrievedKnowledge` item to a
Tool result containing:

- `rank`
- `source` / `source_path`
- `chunk_id`
- `content`
- `score`, `lexical_score`, `vector_score`
- existing `metadata`

`search_knowledge(query, top_k=5)` is registered by the official MCP server,
is returned by `InMemoryMCPToolClient.describe_tools()`, and is accepted by
the normal read-only policy. It is not in `WRITE_TOOL_NAMES` and is never sent
to `WriteActionCoordinator`.

Production wiring passes the existing `KnowledgeService` to the MCP facade and
passes no `AsyncKnowledgeRetriever` to the production workflow. The optional
workflow retriever parameter remains only for historical V0.5 compatibility
tests and evaluation collectors.

## New evaluation contract

The historical 21 Tool Cases were not modified. V1.4.1 uses the separate:

`eval/v1_4_1/rag_as_tool_cases.jsonl`

Cases cover:

1. knowledge-only query where `search_knowledge` is required;
2. live task status where `get_task_detail` is required and RAG is optional;
3. GPU diagnosis combining platform evidence with optional knowledge search;
4. write-boundary protection;
5. no-tool greeting.

Artifact:

`local_acceptance/v1.4.1_rag_tool_eval.json`

The artifact contains the five planner outputs, case metadata, actual tool
arguments, DeepEval scores, and deterministic companion metrics.

## API usage and limitations

Only the five new V1.4.1 Planner cases were sent to qwen-plus; the historical
21 Tool Cases and 30-case Retrieval Evaluation were not rerun. The first two
local collection wrappers failed while serializing their already completed
responses; the final collection was saved unchanged before offline metric
calculation. DeepEval then judged the saved five cases. Exact provider-level
request counting is not exposed by the current adapter, so the artifact records
logical case scope rather than claiming a fabricated wire count.

The V1.4.1 status is `PARTIAL`, not `PASS`, because formal Tool integration is
complete but the real qwen-plus baseline did not yet autonomously select
`search_knowledge` for the required knowledge-only case. This is intentionally
left as an evaluation finding for a later, explicitly approved decision; no
Prompt or Golden Set change is included here.
