# V1.7.0 — Bounded Autonomy

## Overall

V1.7.0 adds one deliberately narrow autonomous mutation slice: a deterministic,
policy-gated `resume_task`. The model can propose a frozen write action, but it
cannot choose `AUTO`; the policy, Platform Core precondition and verification
chain remain authoritative.

`PLATFORM_AGENT_AUTONOMY_ENABLED` defaults to `false`. With the flag disabled,
resume behavior remains the V1.6.4 pending HITL flow.

## Autonomy Scope

| Action | Authorization |
|---|---|
| `resume_task` with all low-risk conditions | `AUTO` eligible |
| `resume_task` with non-failed scope, budget overflow, or possible cross-task preemption | `HITL` |
| `resume_task` with missing target, target conflict, unknown task/dataset, or critical read failure | `DENY` |
| `submit_task`, `set_task_priority`, `stop_task`, `delete_task` | `HITL` only |

The adaptive read-only loop cannot execute write tools and cannot revise a read
intent into a write intent.

## Deterministic Policy

`platform_agent/autonomy.py` is provider-neutral and records only short reasons,
checks, budgets and frozen arguments. AUTO requires all of the following:

- action is exactly `resume_task`;
- exact target task identity is present and consistent in the precondition and
  verification baseline;
- task/config/DAG/Airflow evidence and the verification baseline are usable;
- the latest state per dataset is `failed`, rather than merely having any
  historical failed run;
- explicit datasets are all currently failed and known, or the current failed
  set is deterministically derived when the request omitted datasets;
- the derived scope is frozen into non-empty `arguments.datasets`;
- the scope is within `PLATFORM_AGENT_AUTO_RESUME_MAX_DATASETS` (default `3`);
- the target does not imply automatic cross-task preemption;
- the request has not consumed `PLATFORM_AGENT_AUTO_ACTIONS_PER_REQUEST`
  (default `1`).

The empty dataset list is never passed to an AUTO mutation. The mutation sees the
same frozen dataset scope that the policy evaluated, so a later Airflow change
cannot expand the mutation scope.

## Policy Matrix

```text
safe resume + current failed datasets                  -> AUTO
autonomy disabled                                      -> HITL
selected non-failed dataset                           -> HITL
dataset budget exceeded                               -> HITL
possible cross-task preemption                        -> HITL
missing target / target provenance conflict           -> DENY
task or dataset missing                                -> DENY
critical verification evidence unavailable            -> DENY
submit / priority / stop / delete                     -> HITL
```

## Shared Guarded Execution Chain

AUTO creates an explicit `authorization_mode=auto` execution record. It does not
pretend that a human approved the action. The record enters the same coordinator
execution path as HITL:

```text
deterministic policy
  -> frozen arguments
  -> Platform Core Precondition
  -> mutation
  -> Action Verification
  -> read-only Goal Verification
  -> executed/escalated record
```

`ApprovalStore` keeps mutation lifecycle (`executed`, `failed`,
`verification_failed`) separate from the user Goal lifecycle. Therefore
`Action Verification=VERIFIED` with `Goal Verification=IN_PROGRESS` or
`FAILED` is valid and is never silently promoted to Goal success.

## Budgets and Failure Escalation

The default action budget is one AUTO mutation per request/trace. Any mutation
failure, stale precondition, Action Verification failure, Goal Verification
failure or inconclusive result consumes that attempt and records escalation.
There is no autonomous retry, re-capture-and-execute path, background polling
loop or automatic model failover.

Configuration:

```text
PLATFORM_AGENT_AUTONOMY_ENABLED=false
PLATFORM_AGENT_AUTO_ACTIONS_PER_REQUEST=1
PLATFORM_AGENT_AUTO_RESUME_MAX_DATASETS=3
```

## Safety Invariants

- LLM direct write tool execution: `0`.
- Adaptive write execution: `0`.
- AUTO action allow-list: `resume_task` only.
- HITL remains required for all other writes and whenever policy conditions are
  not sufficient for AUTO.
- Precondition, Action Verification and Goal Verification are not bypassed.
- RAG/knowledge evidence cannot authorize AUTO.
- AUTO does not automatically preempt another task or retry a mutation.
- V1.6.x entity provenance, diagnostic context and multi-dataset Goal
  Verification contracts remain in force.

## Tests and Acceptance

The committed V1.7 acceptance directory records the actual deterministic policy
matrix, autonomy scenarios, targeted commands and model/quota result. The main
coverage includes:

- safe single and multi-dataset AUTO;
- derived dataset scope freeze;
- latest-state versus historical failure;
- non-failed dataset, budget, cross-task, missing-target, unknown-dataset and
  unavailable-evidence decisions;
- stale precondition with exactly one mutation attempt;
- AUTO and HITL record compatibility;
- Action Verification/Goal Verification separation;
- scope drift and duplicate action budget;
- submit/priority/stop/delete HITL preservation;
- V1.6.4 evidence and Goal Verification regressions.

Formal qwen-plus benchmark remains deferred. LLM smoke is a functional signal
only; deterministic policy and safety tests are the release gate.

## Local E2E and LLM Smoke

The deterministic suite should be completed before provider calls. If a Bailian
provider returns `403 AllocationQuota.FreeTierOnly`, the run must stop without
retrying or enabling paid usage. A model switch, if needed for development
smoke, is configuration-only and is not production failover.

## Known Limitations

- Goal Verification proves the bounded post-action evidence contract; it is not
  long-horizon business outcome monitoring.
- Eventual-consistency states may return `IN_PROGRESS` or `INCONCLUSIVE`; the
  bounded slice does not poll or retry autonomously.
- Formal frozen adaptive/qwen-plus benchmark remains deferred until feature
  freeze.

## Recommendation

The final recommendation is recorded from the actual targeted tests, local E2E
availability and functional smoke in `local_acceptance/v1.7.0/`. V1.8 is not
implemented by this version.

With the deterministic and safety gates above green, the recorded recommendation
is `PROCEED_TO_V1.8.0 A+ FINAL HARDENING`. This does not start V1.8 work.
