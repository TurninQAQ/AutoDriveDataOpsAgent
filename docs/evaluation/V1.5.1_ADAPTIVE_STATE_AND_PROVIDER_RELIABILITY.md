V1.5.1 closes the deterministic Adaptive state and Tool Catalog contracts and

The frozen V1.5.0 Scenario Set is not modified.

## Why this version was needed

V1.5.0 had the correct read-only loop mechanics, but a revised intent was only
stored in controller state. The next Provider decision still saw the original
`INITIAL_PLAN.intent` without an explicit current intent or previous decision
context. V1.5.1 passes `CURRENT_INTENT` and bounded structured adaptive history
to every subsequent decision.

The V1.5.0 fixture client also exposed descriptions such as
`description=name`. That was not production-equivalent. A canonical catalog
now supplies names, semantic descriptions and required input fields to the
Facade adapter and deterministic Scenario Fixture. MCP registrations use the
same descriptions.

## Adaptive state closure

```text
Initial Plan
  initial_intent = platform_knowledge
        ↓
Step 1 decision
  revised_intent = task_diagnosis
        ↓
Step 2 decision sees:
  INITIAL_INTENT = platform_knowledge
  CURRENT_INTENT = task_diagnosis
  PREVIOUS_ADAPTIVE_DECISIONS = bounded structured audit fields
```

Only the following previous-step fields are forwarded:

```text
step, action, tool, arguments, revised_intent,
evidence_sufficient, decision_summary
```

No hidden reasoning, chain-of-thought or free-form analysis is stored or sent
as adaptive state. Read-only intent revision remains bounded by
`READ_ONLY_INTENTS`; a mutation revision is rejected before execution.

## Canonical Tool Catalog

`platform_agent/tool_catalog.py` is the single source for the read-only
catalog. It covers:

```text
get_platform_health
list_tasks
get_task_detail
get_queue_state
get_gpu_pool
inspect_task_containers
get_stage_logs
diagnose_task
search_knowledge
```

In particular:

- `get_gpu_pool` means current/live GPU memory, availability and active
  reservations; it does not explain platform reservation rules.
- `search_knowledge` means static documentation, architecture, mechanisms,
  policies and runbooks; it does not return current runtime state.
- `diagnose_task`, `get_task_detail` and `get_stage_logs` declare concrete
  `task_name` as a required field.
- `search_knowledge` declares `query` as required.

Knowledge capability disabled means `search_knowledge` is not exposed by the
Facade catalog. The production MCP surface and dependency-light Fixture use
the same semantic metadata.

## Provider deadline and preflight

`PLATFORM_MODEL_REQUEST_TIMEOUT_SEC` defaults to `45` seconds. The shared
`retry_async()` wraps each provider await with this deadline and classifies
timeouts as retryable transport failures. Existing retry attempts, backoff,
Retry-After and legacy Gemini environment fallback semantics remain unchanged.

The preflight command is:

```text
scripts/check_qwen_provider.py
```

It sends only synthetic structured JSON requests, records endpoint host and
failure class, and never records credentials or response bodies. The V1.5.1
collector requires preflight success before starting any frozen Scenario Case.

Failure classes include:

```text
provider_timeout
provider_connection_error
provider_http_error
provider_invalid_json
provider_auth_error
provider_rate_limit
unknown_provider_error
```

The synthetic Qwen preflight passed 2/2 requests. Formal collection then
started against the frozen V1.5.0 cases and completed three cases before the
next model operation stopped at the proxy response-header wait. The partial
trajectory is preserved, but it is not a valid full Adaptive baseline.

```text

```

The completed trajectories are useful diagnostic evidence only:

- `adaptive_gpu_hybrid_unseen`: `get_gpu_pool` then `search_knowledge`,
  terminated with sufficient evidence.
- `adaptive_known_hybrid_gpu`: `get_gpu_pool` then `search_knowledge`,
  terminated with sufficient evidence.
- `adaptive_known_hybrid_draining`: repeated `search_knowledge` calls,
  without `diagnose_task`; it terminated with insufficient evidence.

The third case confirms that the state-closure plumbing is present in the
runtime, but it does not by itself solve a model's routing decision. The
capability/no-tool case and the remaining 13 frozen cases were not collected.
No full Adaptive score is inferred from this partial provider-blocked run.

## Safety and compatibility

The following remain unchanged:

- no forced retrieval;
- no adaptive write execution;
- HITL, Precondition and Verification;
- TaskPlanningService bypass of the read loop;
- V1.4.x and V1.5.0 deterministic regression contracts;
- Embedding, Chunking, Vector Store and Retrieval algorithms.

Known repository/environment issues remain outside this version: old Nvidia
runtime expectations on a host without a GPU, and a deployment test that calls
an unavailable `python` executable.

## Recommendation

Do not enter V1.6 yet. Preflight is healthy, but a complete frozen qwen-plus
trajectory collection is still required. After the provider response-header
path is available, collect all 16 cases once without changing the cases or
adding case-specific Prompt examples. If the complete baseline shows
systematic Hybrid or termination failures, stay on V1.5.x; otherwise evaluate
the V1.6 boundary from the recorded trajectory metrics.
