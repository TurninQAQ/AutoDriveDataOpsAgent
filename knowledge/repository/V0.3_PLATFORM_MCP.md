# V0.3 Platform MCP Server

## 1. 目标

V0.3 的目标是把 V0.1/V0.2 已经抽出的平台能力暴露为 **只读 MCP Tool**，暂时不接 LLM，也不开放任何修改平台状态的能力。

核心边界：

```text
MCP Client
    ↓
platform_mcp
    ↓
Platform Core
    ↓
Airflow / Queue / Docker / GPU Runtime
```

MCP 层不能直接修改：

- Airflow DagRun / TaskInstance
- Docker Container
- Queue State
- GPU Reservation
- Task YAML

## 2. MCP SDK

使用官方 MCP Python SDK v2：

```text
mcp==2.0.0
```

服务类：

```python
from mcp.server import MCPServer
```

Transport：

```text
stdio
```

V0.3 不实现 HTTP Transport，避免提前引入部署、认证和网络层复杂度。

## 3. Tool 列表

### get_platform_health

聚合：

- Airflow `/api/v2/monitor/health`
- Queue 文件可读状态
- Docker binary
- Task Config Root
- GPU Runtime

### list_tasks

从 Task Config Root 枚举平台业务任务，返回：

- task_name
- dag_id
- priority
- task_type
- datasets
- pipeline_stages
- queue status

### get_task_detail

返回：

- Task YAML 核心配置
- Pipeline
- Dataset
- GPU 配置
- Queue State
- 最近 Airflow DagRun

### get_queue_state

不传 task_name：

```text
返回全局 active / queued / draining 状态
```

传 task_name：

```text
返回指定业务任务在全局队列中的位置
```

### get_gpu_pool

返回：

- GPU total/used/free memory
- active reservation
- task/dataset/stage
- required_mb
- exclusive

支持清理死亡 PID 对应的 stale reservation。

### inspect_task_containers

按照现有 Docker 精准匹配规则查询业务任务容器。

支持 Dataset 范围限制。

### get_stage_logs

通过 Airflow REST API 获取：

- 最新匹配 DagRun
- run_<stage>
- validate_<stage>
- try_number
- log tail

未指定 Stage 时优先返回 failed / upstream_failed / running TaskInstance 的日志。

### diagnose_task

聚合：

```text
Queue
+
Airflow DagRun
+
TaskInstance
+
Docker Container
+
GPU Reservation
+
GPU Runtime
```

V0.3 **不输出 Root Cause**。

只输出 Evidence 和采集错误。

Root Cause 推理留到 V0.4 Read-only Agent。

## 5. Airflow Read API

V0.3 使用 Airflow 3 REST API：

```text
GET /api/v2/monitor/health
GET /api/v2/dags/{dag_id}/dagRuns
GET /api/v2/dags/{dag_id}/dagRuns/{run_id}/taskInstances
GET /api/v2/dags/{dag_id}/dagRuns/{run_id}/taskInstances/{task_id}/logs/{try_number}
```

认证复用现有平台：

```text
AIRFLOW_API_TOKEN
```

或者：

```text
AIRFLOW_API_USER
+
AIRFLOW_API_PASSWORD
```

如果没有显式密码，则读取现有：

```text
AIRFLOW_PASSWORD_FILE
```

## 6. stdio 安全

MCP stdio 的 stdout 是协议通道。

现有平台部分遗留方法会 `print()`。

因此 PlatformMCPFacade 在调用 Platform Core 时统一：

```text
stdout → stderr
```

避免旧日志污染 MCP JSON-RPC/MCP 协议输出。

## 7. Runtime 安装


```text

```

```text
$RUNTIME_DIR/bin/mcp-server
```

```bash
$RUNTIME_DIR/bin/mcp-server
```

默认使用 stdio。

## 8. 本地无 GPU

继续使用 V0.2：

```bash
export PLATFORM_GPU_RUNTIME=simulated
export PLATFORM_GPU_SIM_CONFIG=/path/to/config/gpu_simulator.yaml
export PLATFORM_GPU_SIM_STATE=/tmp/platform/state/gpu_simulator.json
```

MCP Tool 查询的是和平台 Stage 相同的 SimulatedGPURuntime 和 GPU Reservation 文件。

不存在另一套 MCP 专用 GPU Mock。
