# V0.7 Write Agent + HITL + Precondition

## 1. 目标

V0.7 在 V0.6 自然语言 Task Planning 基础上开放第一批平台写操作，但所有写操作必须经过：

```text
User Request
  -> Agent Plan
  -> Read-only Impact Evidence
  -> Deterministic Impact Analysis
  -> Pending Approval (persisted)
  -> Human approve/reject
  -> Precondition Recheck in Platform Core
  -> Write MCP Tool
```

V0.7 不做 V0.8 的统一 Action Verification。Write Tool 返回成功仅表示本次平台写调用完成；后续“重新 Observe 并确认业务状态达到目标”的统一闭环放在 V0.8。

## 2. Write MCP Surface

V0.3 的 8 个 read-only Tool contract 保持不变。

V0.7 新增两个写前准备 Tool：

- `get_write_precondition`
- `validate_task_spec`

新增五个 Write Tool：

- `submit_task`
- `resume_task`
- `set_task_priority`
- `stop_task`
- `delete_task`

普通 planning model 的 `tool_calls` 仍然只能调用 V0.3 的 read-only Tool。Write Tool 只允许 `WriteActionCoordinator` 在 persisted approval 被显式 approve 后调用。

## 3. Platform Core Mutation Boundary

新增：

- `platform_core/mutation.py`
- `platform_core/services/precondition_service.py`
- `platform_core/services/mutation_service.py`
- `platform_core/gateways/legacy_mutation.py`

### 3.1 确定性校验

`submit_task` 在 Write Boundary 再次调用现有 `platform_core.config.validate_config()`。

因此：

```text
LLM extraction
  -> V0.6 TaskPlanningResult.valid
  -> validate_task_spec MCP
  -> PlatformMutationService.validate_task_spec
  -> existing validate_config
```

任何一层失败都不能 submit。

### 3.2 Legacy Mutation Gateway

V0.7 没有重新实现已经成熟的 Queue / Soft Preemption / Recovery / Docker cleanup 编排。

`LegacyMutationGateway` 通过 Python import 调用现有 `scripts.task_manager` 函数：

- `submit`
- `resume_task`
- `set_task_priority`
- `stop_task`
- `delete_task_by_name`

Agent/MCP 不执行任意 shell，不拼接 CLI 字符串。

该 Gateway 是迁移期兼容层，目的是让 Agent 写入口复用现有生产语义。后续可继续逐步将 legacy orchestration 下沉到 Platform Core，但不应在 V0.7 重写软抢占/恢复逻辑。

## 4. Precondition

Approval 创建时保存：

```text
queue_sha256
task_name
task_config_sha256
task_exists
active_task_name
```

执行前 Platform Core 重新计算。

如果 Human Review 期间 Queue 或 Task Config 发生变化，返回：

```text
PRECONDITION_FAILED
```

并且 mutation gateway 不会被调用。

这是 optimistic concurrency control，用于避免：

```text
Observe state A
  -> Human Approval
  -> platform already changed to state B
  -> execute stale plan
```

## 5. HITL Approval Store

新增：

- `platform_agent/approval.py`
- `platform_agent/actions.py`

Approval 使用本地文件持久化，默认目录：

```text
$AIRFLOW_STATE_DIR/agent_approvals
```

环境变量：

```text
PLATFORM_AGENT_APPROVAL_DIR
PLATFORM_AGENT_APPROVAL_TTL_SEC=900
```

状态机：

```text
pending
  -> executing
      -> executed
      -> failed
  -> rejected
  -> expired
```

每个 approval 使用独立 `fcntl` 文件锁。

`pending -> executing` 是原子 claim，因此两个进程不能同时执行同一个 approval。

## 6. Approval 冻结内容

Pending Approval 固化：

- tool name
- exact tool arguments
- precondition
- risk level
- impact summary
- impact details
- user request
- thread id
- expiry

approve 时不会重新询问 LLM 生成参数。

即：

```text
Human approved X
```

执行的一定还是 X，而不是 approval 后模型重新生成的 Y。

## 7. Risk Policy

V0.7 风险等级：

| Tool | Risk |
|---|---|
| resume_task | medium |
| submit_task | high |
| set_task_priority | high |
| stop_task | high |
| delete_task | destructive |

所有五个 Write Tool 都要求显式 approval。

`restart_platform` 当前仍不进入 Agent Write Surface。

## 8. Agent Write Intent

新增：

- `submit_task`
- `resume_task`
- `set_task_priority`
- `stop_task`
- `delete_task`

`AgentPlan` 新增：

```text
write_action
```

Write Intent 的 `tool_calls` 只能用于读取 Impact Evidence，例如：

```text
get_task_detail
get_queue_state
```

Write Tool 本身绝对不能出现在 model-generated `tool_calls` 中。

如果模型伪造：

```text
tool_calls=[delete_task]
```

Policy 会在执行前抛出 PermissionError。

## 9. Submit 特殊规则

Submit 必须使用 V0.6 `TaskPlanningService`。

流程：

```text
Natural Language
 -> task_draft
 -> TaskPlanningService.plan_from_draft
 -> TaskPlanningResult.valid
 -> validate_task_spec MCP
 -> approval
 -> submit_task MCP
```

未通过 `TaskPlanningResult.valid`：

- 不创建 approval
- 不调用 validate_task_spec
- 不调用 submit_task

## 10. Priority 特殊规则

Agent 不推断具体 priority。

例如：

```text
让 release_xxx 先跑
```

如果用户没有提供明确数字，V0.7 不会自动猜 `0/1/5`，也不会创建 approval。

用户必须明确：

```text
把 release_xxx 优先级改成5
```

## 11. CLI

写请求：

```bash
dataops-agent ask '把 release_xxx 优先级改成5'
```

返回 `approval_id`，此时没有执行 mutation。

查看：

```bash
dataops-agent approvals
```

审批：

```bash
dataops-agent approve <approval_id>
```

拒绝：

```bash
dataops-agent reject <approval_id>
```

Approval 过期或已经被另一个进程 claim 后不能再次执行。

## 12. V0.7 与 V0.8 边界

V0.7 完成：

```text
Observe for impact
 -> Approval
 -> Precondition
 -> Act
```

V0.8 才实现统一：

```text
Act
 -> Observe Again
 -> Verify Goal State
 -> success / diagnosis
```

不要在 V0.7 把 Tool 返回 `ok=true` 等价成业务目标一定达成。
