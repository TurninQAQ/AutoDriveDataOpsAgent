# V0.6 Natural Language Task Planning

## 1. 目标

V0.6 在 V0.5 Read-only Agent + RAG 上增加自然语言任务规划能力，但仍不允许 Agent 修改运行中的平台状态。

固定链路：

```text
Natural Language
    -> Structured task_draft
    -> Platform deterministic defaults
    -> TaskSpec
    -> platform_core.config.validate_config()
    -> YAML preview / local YAML file
```

V0.6 不执行：

```text
submit / trigger / start / priority / stop / delete / resume / restart
```

生成本地 YAML 不等价于提交任务。

## 2. 核心设计

### 2.1 新增 `platform_planning`

`platform_planning` 不依赖 Airflow Runtime，也不调用 TaskService.submit 路径。

主要模块：

- `models.py`：`TaskSpec`、`DatasetSpec`、`TaskPlanningResult`、`ValidationIssue`
- `defaults.py`：加载确定性平台默认值
- `heuristic.py`：无模型 Key 时的本地自然语言抽取
- `service.py`：Draft 合并、TaskSpec 构造、现有 validator 复用、YAML 输出
- `evaluation.py`：固定 Task Planning Eval

### 2.2 LLM 只负责抽取，不负责合法性

OpenAI-compatible Planner 的 `AgentPlan` 新增：

```text
intent=task_planning
task_draft={...}
tool_calls=[]
```

`task_draft` 只能表达用户显式提供的信息。

缺省值来自：

```text
config/task_planning_defaults.yaml
config/task_types.yaml
```

最终合法性继续由：

```python
platform_core.config.validate_config(config)
```

判断。

因此模型不能绕过：

- Stage script 是否存在
- GPU Stage / Memory 配置是否完整
- Pipeline Stage 是否重复
- Dataset 是否缺 image_<stage>
- max_active_runs 是否合法
- task_type / priority 是否合法

### 2.3 默认值来源

新增：

```text
config/task_planning_defaults.yaml
```

其中维护：

- 默认 Pipeline
- max_active_runs
- task_exclusive / preempt 参数
- GPU IDs
- GPU Stage
- 独占 Stage
- Stage 显存
- Dataset tier/pool/timeout
- 当前平台默认镜像

Planner 不从 LLM 猜测这些值。

默认镜像使用仓库当前已有的具体镜像版本，不使用模板中的 `xxx` placeholder。

环境变量：

```text
PLATFORM_TASK_PLANNING_DEFAULTS
```

Runtime 默认：

```text
$AIRFLOW_CONFIG_DIR/task_planning_defaults.yaml
```

## 3. 本地 Heuristic Planner

当前无 API Key 时支持常见语义：

- release / reprocess / test / debug task_type
- 任务名 / task prefix
- priority
- 完整流程
- `只运行 od`
- `pipeline=precheck,parser,[od,occ],coloration`
- max_active_runs / 并发 Clip 数
- Dataset path
- `clip_001 clip_002`
- GPU IDs
- `segment 24GB`
- `segment和od独占GPU，occ共享GPU`
- `image_segment=registry/image:tag`
- timeout

Heuristic 只是开发/回归 Provider，不取代结构化 LLM Planner。

## 4. Agent Workflow 变化

V0.5：

```text
plan -> retrieve -> tools -> answer
```

V0.6 对 `task_planning` 增加特殊确定性分支：

```text
User
 -> Policy
 -> Agent Planner
 -> task_draft
 -> TaskPlanningService
 -> deterministic validation
 -> AgentResponse.task_plan
```

Task Planning 不需要 MCP 实时状态，因此：

- 不调用 MCP Tool
- 不读取实时 Queue / GPU / Docker / Airflow
- 不建立写操作

`AgentResponse` 新增：

```text
task_plan
```

包含：

- valid
- task_spec
- config
- yaml_text
- resolved_priority
- priority_source
- defaults_used
- explicit_fields
- unresolved_fields
- issues

## 5. Policy 变化

V0.4/V0.5 将 `create task` 全部视为 mutation。

V0.6 改为：

```text
创建/生成任务配置 -> 允许，只生成 TaskSpec/YAML
提交/触发/启动任务 -> 继续禁止
```

例如：

```text
创建一个 release 任务，生成 YAML
```

允许。

```text
创建一个 release 任务并提交
```

在 Model / Tool 前直接拦截。

## 6. CLI

直接规划：

```bash
python3 scripts/dataops_agent.py plan-task \
  '创建一个release任务，把 /data/record_001 做完整流程，最多同时4个clip，segment和od独占GPU，occ共享GPU'
```

写本地 YAML：

```bash
python3 scripts/dataops_agent.py plan-task \
  '创建一个test任务，只运行 precheck，数据 /tmp/record_a' \
  --output /tmp/task.yaml
```

无效 TaskSpec 不允许写文件。

普通 Agent 路径也支持：

```bash
PLATFORM_AGENT_RUNTIME=sequential \
PLATFORM_AGENT_PROVIDER=heuristic \
python3 scripts/dataops_agent.py ask \
  '创建一个release任务，把 /data/record_001 做完整流程'
```

## 7. Eval

固定 Case：

```bash
python3 scripts/dataops_agent.py plan-task-eval
```

当前：

```text
8 cases
8 passed
accuracy=1.000
```

覆盖：

- Release 全流程 + GPU 独占/共享
- CPU-only precheck
- 显式 priority / memory
- 缺 dataset path
- 并行 pipeline literal
- task_type 默认 priority
- 非法 Stage
- 多 Clip 共用 Record path

## 8. V0.6 边界

本版本明确不做：

1. 不新增 Write MCP Tool。
2. 不 submit Task。
3. 不 trigger DagRun。
4. 不修改 Priority。
5. 不 stop/delete/resume。
6. 不做 HITL approval。
7. 不做 Action Verification。
8. 不让 RAG 生成实时 Task 状态。
9. 不让 LLM 自己生成平台默认镜像/GPU 参数。

V0.7 才进入 Write Tool + HITL。
